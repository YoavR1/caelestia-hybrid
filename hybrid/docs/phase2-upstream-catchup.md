# Phase 2 — upstream catch-up

Merging `caelestia/main` (51 commits) into the MiDnight baseline. Branch
`phase2/upstream-catchup`. **The merge commit on that branch does not build yet** — one file
is left, and it is named below. `phase0/scaffold-and-ci` is untouched and fully green.

Merge base `ad8dca0a`. 197 files, +6549/−5198 incoming. 35 conflicts.

## What upstream changed

Two commits dominate:

- **`6cbc70b4 refactor(config): rewrite config module`** — the generic node machinery moved
  out of `Config/` into a new `Caelestia/Settings` module (`macros.hpp`, `objectnode.hpp`,
  `listnode.hpp`, `rootnode.hpp`, `schema.cpp`, `codecs.cpp`, `quarantine.cpp`,
  `settingsfile.cpp`, `layerregistry.hpp`). `Config/common.hpp` is now a thin alias layer:
  `CONFIG_PROPERTY` → `SETTINGS_PROPERTY`, and so on.
- **`a3425d59 refactor: rearrange plugin layout`** — include prefixes, cross-module headers
  by named prefix.

Everything else is a style/perf sweep (`u""_s` over `QStringLiteral`, scoped enums,
`QT_NO_CAST_FROM_ASCII`, clang-tidy, sorted includes) plus a few bar features.

### API mapping

| old (MiDnight) | new (upstream) |
|---|---|
| `class X : public ConfigObject { Q_OBJECT QML_ANONYMOUS` | `class X : public settings::ObjectNode { CONFIG_NODE(X, settings::ObjectNode)` |
| explicit ctor with `m_a(new A(this))` initialisers | generated by `CONFIG_NODE` — delete the ctor |
| `CONFIG_SUBOBJECT(EntryList, x)` + ctor defaults | `CONFIG_LIST(EntryList, x, DEFAULT_ARG({...}))` |
| `loadFromJson(json)` | `syncJson(json, diagnostics)` |
| `toJson()` | `toJson(bool sparse)` |
| `markPropertyLoaded(key)` | gone — `syncJson` returns a visited set |
| `unknownKeys()` / manual custom-key tracking | `settings::Quarantine` — kept and re-applied on save |
| `MonitorConfigManager` | `settings::LayerRegistry<Root>` + `Root::forScreen()` |
| `GlobalConfig` (was `RootConfig`) | `ConfigSingleton : ConfigRoot`, QML name unchanged |
| `CONFIG_PROPERTY(QStringList, x)` | a default is now mandatory: `..., x, {})` |

`hybrid/tools/` has no fixer for this; the port was `resolve.py` (side selection) plus a
one-off `portnode.py`, both in the session scratchpad. Neither is worth keeping — the
transformation happens once.

## Conflict resolutions

**Accepted upstream's deletion (9 files).** `config.{cpp,hpp}`, `configlist.{cpp,hpp}`,
`configobject.{cpp,hpp}`, `rootconfig.{cpp,hpp}`, `monitorconfigmanager.cpp`. Checked first
that **no QML file references `MonitorConfigManager`** — it was C++-internal, and
`LayerRegistry` + `monitorConfigDir()` replace it exactly. `confignode.*` and `tokens.cpp`
went the same way.

`winfoconfig.hpp` is also gone. Upstream deleted it and MiDnight never modified it, so it
merged away silently — verified safe: `WInfoConfig` had **no properties at all** (the class
comment says so) and nothing referenced it. The winfo *tokens* live in `tokens.hpp` and are
untouched.

**Rebuilt from upstream + MiDnight's additions rather than resolved hunk-by-hunk.**
`barconfig.hpp`, `launcherconfig.hpp`, `utilitiesconfig.hpp`. Taking a side per hunk cut
across `CONFIG_LIST(...)` macro invocations and produced files that looked plausible and
would not preprocess (`missing ')' in macro usage`). For anything where upstream restructured
the macro, take upstream's file whole and re-apply the delta.

**MiDnight's `BarSections` ported to the new API.** Its three `EntryList` subobjects became
`CONFIG_LIST` declarations with inline defaults, which removed the custom constructor
entirely. Its `loadFromJson` override — which migrates upstream's flat `bar.entries` array
into start/center/end — became a `syncJson` override that builds the object the base class
would have received and delegates, instead of loading each list by hand and marking it
visited.

**MiDnight's `Videos` filter ported into upstream's `filtersFor()`** in
`filesystemmodel.cpp` rather than reinstated as a branch of the old scan loop. Upstream's
refactor already covers the `Images` case exactly as MiDnight did it. `FollowSymlinks` is
kept — wallpaper directories are commonly symlinked.

**Kept MiDnight's side, deliberately** — recorded here because each is a deferred re-import:

| file | what upstream has that we did not take |
|---|---|
| `modules/bar/components/workspaces/Workspace.qml` | `32ee2750` material-shape workspace indicators |
| `plugin/.../barconfig.hpp` `BarWorkspaces` | `BarWorkspaceDisplay` / `BarWorkspaceCapitalisation` enums (`f43e1dd2`, `88959e9c`) |

The workspace ones are one decision, not three: MiDnight renders workspaces itself and its
QML reads `useIcon` and a plain-string `capitalisation`. Converging on upstream's enums means
taking upstream's `Workspace.qml` with it, which drops MiDnight's labels. D1 makes MiDnight
the baseline, so its version stays until someone decides otherwise. Upstream's additive
`ignoredTags` was taken.

The README is neither project's: MiDnight's documents a fork we are not shipping, upstream's
documents a shell we are not shipping. It needs a Hybrid rewrite, and until then keeping ours
at least lists features that exist.

**Took upstream's side**: `.envrc` (its clazy/ccache detection is strictly better),
`appearanceconfig`/`generalconfig`/`lockconfig`/`tokens`/`font`/`configattached`/`toaster`
structure, with MiDnight's properties re-added on top — `pitchBlack`, `islands`,
`developerMode`, `lockOnStartup`, the three mono font-size tokens, the two window-switcher
size tokens, the `shimeji` attached-config accessor, the toast icon.

## What is left

**`plugin/src/Caelestia/Config/sessionconfig.{hpp,cpp}` — 633 lines, the only thing that
does not compile.** MiDnight added user-defined session buttons: arbitrary keys under
`session.icons` and `session.commands`, surfaced to QML as `Config.session.buttons` and
`Config.session.customButtons` (used by `modules/session/Content.qml` and
`modules/lock/Resources.qml`). It implements that by overriding seven `ConfigObject`
virtuals that no longer exist: `loadFromJson`, `toJson`, `clearLoadedKeys`, `unknownKeys`,
`resyncFromGlobal`, `syncValuesFromGlobal`, `onGlobalPropertiesChanged`, plus `childNodes`.

The port is smaller than it looks, because **upstream built the mechanism MiDnight
hand-rolled**. `ObjectNode::syncJson` already quarantines unknown keys, and `toJson` already
re-applies them (`m_quarantine->apply(json)`), so custom buttons round-trip through the file
for free. What remains is to override `syncJson` to also record the custom keys in file
order and expose them, then rebuild `buttons()`/`customButtons()` on top.

One thing genuinely goes away: `rootconfig.cpp` carried ~170 lines of `reorderJsonBlockKeys`,
hand-written JSON string surgery that re-ordered `session.icons` and `session.commands` on
save because `QJsonObject` sorts its keys. Upstream's quarantine is a `QHash`, so it does not
preserve order either. **Decide before finishing:** accept that custom session buttons
reorder alphabetically after a save, or store an explicit order array. Do not port the string
surgery — it will not survive the next upstream sync.

After that compiles, none of the QML has been checked against the new singletons yet, and
none of the five gates has been run on this branch.
